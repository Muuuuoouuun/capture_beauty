# g2 다음 단계 및 로드맵

## 0. 현재 상태 요약
- MVP 기본 뼈대(홈/검색/리뷰/API/데이터/기초 테스트)는 구축됨
- 리뷰 화면에 비교표, 점수, 실무 가이드, 패치/에러 기록 UI까지 포함됨
- 다만 실행/배포 관점에서 의존성 설치 이슈(환경 registry 권한)가 있어 런타임 검증 자동화가 제한됨

---

## 1. 제품 우선순위 (사용자 가치 기준)
1. **문제 해결 속도 향상**: 사용자가 "내 상황"에 맞는 도구를 30초 내 찾게 만들기
2. **판단 신뢰도 강화**: 점수/비교/패치 이력 근거를 표준화해 리뷰 신뢰 확보
3. **실무 전환성 확보**: 실제 도입 체크리스트 + 운영 가이드 제공
4. **운영 편의성 강화**: 회사 담당자 입력(패치/이슈/리뷰)을 서버 저장으로 전환

---

## 2. 단계별 로드맵

## Phase 1 (1~2주): 신뢰 가능한 데이터 입력/저장 전환
### 목표
로컬 저장(LocalStorage) 기반 입력을 실제 운영 가능한 서버 저장으로 전환

### 작업 항목
- [ ] DB 스키마 확장
  - review_scores (총점/세부점수)
  - user_reviews (한줄평/상세리뷰)
  - patch_updates (변경사항/리스크/작성자)
  - capability_matrix (비교 기준 항목)
- [ ] 관리자 인증/권한 모델 적용 (admin id + role)
- [ ] `POST/PUT/GET` API 추가 및 검증 스키마 확장
- [ ] 감사 로그(누가/언제/무엇 수정) 최소 단위 적용

### 산출물
- 서버 저장형 리뷰/패치 노트
- 담당자 입력 데이터의 이력 추적 가능 상태

---

## Phase 2 (2~3주): 검색/비교 UX 고도화
### 목표
"비슷한 기능인데 어디가 다르고 무엇이 안되는지"를 즉시 파악 가능하게 개선

### 작업 항목
- [ ] 비교표를 체크리스트형으로 확장 (지원/부분지원/미지원)
- [ ] 필터에 "팀 규모", "업무 유형", "도입 난이도" 추가
- [ ] 검색 결과 카드에 핵심 차이점 1줄 요약 노출
- [ ] 패치 이력에 영향도(High/Medium/Low) 및 장애 여부 표시

### 산출물
- 사용자 관점의 빠른 선택/배제 UX
- 의사결정에 바로 쓰는 비교 데이터

---

## Phase 3 (2주): 실무 도입 가이드 제품화
### 목표
도구 추천을 넘어 "실제로 잘 쓰는 방법"까지 제공

### 작업 항목
- [ ] 실무 플레이북 템플릿화 (직무별: PM/마케팅/세일즈/엔지니어링)
- [ ] "첫 2주 온보딩 플랜" 자동 제안
- [ ] 실패 패턴/안티패턴(과도한 자동화, 과도한 커스터마이징 등) 콘텐츠화
- [ ] 도입 전 체크리스트 및 리스크 점검표 제공

### 산출물
- 업무 적용 가능한 실행형 리뷰
- 도입 실패율을 줄이는 가이드

---

## Phase 4 (1~2주): 품질/운영 안정화
### 목표
서비스 운영 품질과 릴리즈 신뢰성 확보

### 작업 항목
- [ ] API 통합 테스트 + E2E 테스트 구축
- [ ] 에러 추적(Sentry 등) 및 로깅 대시보드 적용
- [ ] CI 파이프라인(테스트/빌드/배포) 구성
- [ ] 성능 최적화 (검색 응답/페이지 로딩)

### 산출물
- 재현 가능한 품질 관리 체계
- 장애 대응력 강화

---

## 3. KPI 제안
- 검색 후 상세 페이지 진입률
- 리뷰 열람 후 북마크/저장률
- 비교표 열람 후 도구 선택 전환율
- 패치 이력 확인 비율(운영 담당자)
- 사용자 리뷰 작성률(한줄평/상세리뷰)

---

## 4. 리스크 및 대응
- **데이터 신뢰 리스크**: 주관적 리뷰 편향
  - 대응: 리뷰 근거 필드 의무화 + 작성자 메타데이터
- **운영 리스크**: 업데이트 누락
  - 대응: 패치 노트 리마인더/검수 워크플로우
- **기술 리스크**: 환경 의존성 설치 실패
  - 대응: 사내 npm proxy 또는 lockfile + 내부 레지스트리 미러 구성
