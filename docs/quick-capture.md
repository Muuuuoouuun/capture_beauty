# 퀵 캡처 구상 — "창 안 띄우고 바로 캡처"

목표: **프로그램 창이나 전체화면 UI 를 띄우지 않고도** 위젯·빠른 동작으로 즉시 캡처를 끝내는 경험.
유명 캡처 도구들의 패턴을 분석하고, 웹 플랫폼 제약 안에서 같은 경험을 만드는 설계를 정리한다.

## 1. 유명 도구들이 "즉시성"을 만드는 방법

| 도구 | 핵심 패턴 | 관찰 |
|---|---|---|
| **Windows** Win+Shift+S (캡처 도구) | 전역 단축키 → 화면 어두워지며 영역 선택 → 자동 클립보드 복사 → 토스트 알림(클릭 시 편집) | 앱 창은 편집을 "원할 때만" 등장 |
| **macOS** Cmd+Shift+3/4/5 | 전역 단축키 → 즉시 촬영 → **우하단 플로팅 썸네일**(몇 초 후 자동 저장, 클릭 시 편집). Cmd+Shift+5 는 작은 **컨트롤 스트립**만 표시 | "썸네일 = 선택적 편집 진입점" 이 UX 의 핵심 |
| **ShareX** | 전역 단축키 → **캡처 후 자동 워크플로우**(저장→복사→업로드→알림)를 사용자가 조립 | 캡처 후 동작 자동화가 창을 대체 |
| **CleanShot X** | 캡처 후 **퀵액세스 오버레이**(작은 카드)에서 복사/저장/주석 선택 | 결과물이 작은 카드로만 존재 |
| **Snagit** | 화면 가장자리에 붙는 **캡처 위젯**(호버 시 확장) | 항상 떠 있는 초소형 진입점 |
| **Lightshot / Flameshot** | 트레이 아이콘 + 전역 단축키 + 영역 선택 오버레이 | 트레이 = 상주형 진입점 |

공통 구조: **① 상주형 초소형 진입점(단축키/트레이/위젯) → ② 촬영 → ③ 자동 동작(복사/저장) → ④ 선택적 편집 진입(썸네일/토스트)**.
본편집 UI 는 이 흐름 어디에도 강제로 등장하지 않는다.

## 2. 웹 플랫폼 제약과 우회

| 제약 | 내용 | 우회 |
|---|---|---|
| 전역 단축키 불가 | 브라우저 탭이 포커스를 잃으면 키를 받을 수 없음 | **PiP 위젯**(아래) — 위젯은 항상 위에 떠 있어 클릭 진입점이 됨 |
| 캡처마다 선택창 | `getDisplayMedia` 는 호출 시마다 화면 선택 UI 표시 | **연속 캡처 세션** — 스트림을 유지하면 이후엔 선택창 없이 프레임만 뜸 |
| 트레이 아이콘 불가 | 웹앱은 OS 트레이 접근 불가 | PiP 위젯이 트레이+컨트롤 스트립 역할 대체 |
| OS 알림/자동 저장 경로 | 저장 위치 선택 불가(다운로드 폴더) | 자동 복사를 기본값으로, 자동 저장은 옵션 |

## 3. 구현 (이 저장소)

### ① 연속 캡처 세션 — `src/quickcapture.ts` `CaptureSession`
화면 공유를 **한 번만** 허용받아 `MediaStream` 을 유지. 이후 셔터는 `video` 프레임을
즉시 캔버스로 떠서(선택창 0회) Win+Shift+S 급 즉시성을 얻는다.
사용자가 브라우저의 "공유 중지"를 누르면 `track.ended` 로 감지해 상태를 되돌린다.

### ② PiP 위젯 — `src/widget.ts` (Document Picture-in-Picture, Chrome 116+)
**모든 앱 위에 항상 떠 있는** 초소형 창(320×132)에 셔터·연결 토글·편집 버튼·최근 썸네일을 담았다.
브라우저 탭을 최소화해도 위젯만으로 [연결 → 셔터 → 자동 복사] 가 끝난다.
권한 요청(getDisplayMedia)은 위젯 창의 사용자 제스처 컨텍스트로 직접 호출한다.

### ③ 퀵 동작 — ShareX 식 캡처 후 파이프라인 (설정 › 캡처)
`캡처 → (자동 여백 제거) → (자동 클립보드 복사) → (자동 저장)` 을 토글로 조립.
기본값: 퀵 캡처 ON + 자동 복사 ON.

### ④ 플로팅 썸네일 — macOS 식 선택적 편집 진입점
캡처 직후 우하단에 썸네일 카드가 몇 초 떠 있다 사라진다(호버 시 유지).
클릭하면 그때만 편집 창이 열린다. 표시 시간은 설정에서 조절(0 = 끔).

### 흐름 요약
```
[위젯 🧷 or 연속 캡처 🔗]  ←  최초 1회 화면 연결
        │ 셔터 (선택창 없음)
        ▼
  퀵 동작: 트림 → 복사/저장          ← 창 전환 0회
        │
        ▼
  플로팅 썸네일 (몇 초)  ── 클릭 ──▶  편집 창 (원할 때만)
```

## 4. 데스크톱 래퍼 (Electron — 구현됨, `desktop/`)

웹에서 불가능했던 마지막 조각을 얇은 Electron 래퍼로 채웠다. 렌더러는 웹앱(dist/)을 그대로 재사용한다.

```bash
npm run build && npm run desktop
```

| 웹의 한계 | 데스크톱에서의 해결 |
|---|---|
| 전역 단축키 불가 | `globalShortcut` — 기본 `Ctrl/Cmd+Shift+1` 빠른 캡처(창 안 뜸, 퀵 동작만), `Ctrl/Cmd+Shift+2` 캡처 후 편집. 설정 › 캡처의 "전역 단축키" 섹션에서 변경·영구 저장 |
| 트레이 불가 | 트레이 아이콘 + 메뉴(빠른 캡처/캡처 후 편집/창 열기/종료). 창 닫기 = 트레이로 최소화 |
| 캡처마다 선택창 | `desktopCapturer` 로 주 화면을 **선택창 없이** 즉시 캡처. 렌더러의 `getDisplayMedia` 도 자동 승인 → 연속 캡처 역시 무선택창 |
| 자기 창이 찍힘 | 캡처 직전 창 자동 숨김(280ms) 후 복원 |
| 클립보드 포커스 제약 | 메인 프로세스가 OS 클립보드에 직접 복사 (`ClipboardItem`) — 백그라운드에서도 동작 |

구성: `desktop/main.cjs`(메인 프로세스) · `desktop/preload.cjs`(contextBridge → `window.native`) ·
`desktop/config.cjs`(accelerator 검증, 단위 테스트 대상) · `src/native.ts`(렌더러 브리지 타입/연동).
배포 패키징이 필요하면 `electron-builder` 를 얹으면 된다.

**영역 선택 오버레이 (구현됨, `src/region.ts`)**: 전체 스크린샷을 뜬 뒤 점선 마칭앤츠 +
바깥 딤 + 실시간 픽셀 크기 배지로 드래그 선택(Win+Shift+S / Cmd+Shift+4 방식). 웹·데스크톱
공용이며, 데스크톱에서는 선택 동안 창을 전체화면으로 전환해 스크린샷이 실제 화면과 1:1 로
겹쳐 보인다. 리뷰 화면의 "⬚ 자르기"도 같은 오버레이를 재사용한다. PWA 설치는 선택지로 유지.

## 5. 검증

- `scripts/e2e.mjs` [11]~[13] (웹): 세션 유지→즉시 grab→해제(스트림 주입으로 결정적 검증),
  퀵 캡처 썸네일 표시/닫기, PiP 위젯 열기/닫기 — 실제 Chromium 에서 통과.
- `scripts/e2e-desktop.mjs` (데스크톱): 실제 Electron 을 Xvfb 에서 구동 —
  전역 단축키 등록/변경/정규화, desktopCapturer 실화면 캡처, 셔터 시 창 숨김·복원,
  전역 단축키 캡처→퀵 파이프라인→OS 클립보드 복사 확인, 닫기=트레이 유지. 전체 통과.
  (리눅스 헤드리스에서는 `xvfb-run -a npm run e2e:desktop`)
- `tests/quickcapture.test.ts`, `tests/desktop-config.test.ts`: 퀵 설정·accelerator 정규화.
